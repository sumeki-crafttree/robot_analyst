# ロボエコノミスト 要件定義（概要 / System Requirements Overview）

**版**: v2.1（2026年8月20日）
**上位文書**: [ミッション・ビジョン](01_mission_vision.md) / [要求定義](02_requirement_business.md)
**位置づけ**: 要求定義の「何を・なぜ」を、システムが満たすべき「何ができていなければならないか」に翻訳する。技術選定・データソース個別名・実装方式は本書では規定せず、下位の設計書に委ねる。

---

## 1. 導出の前提

- 本書は既存実装の説明ではなく、要求定義からの演繹である。
- 設計判断は、要求定義§3の「タイムラグ・感応度・閾値による体系化」に従って解決する。
- 判断が競合する場合は、要求定義§5の「根拠追跡性と再現性が精度に優先する」を上位規範とする。

## 2. 中核データモデル要件

- システムの中心は、レポートでもダッシュボードでもなく、**顧客ごとに構築・保守される「翻訳モデル」**である。
- 翻訳モデルは以下の5要素を保持する構造化資産でなければならない。

| 要素 | 保持すべき内容 |
|---|---|
| マクロ変数 | 観測対象の指標と、その平常レンジ・警戒閾値 |
| 伝達経路 | どの事業セグメントのどのKPIを経由して業績に至るか |
| 感応度 | 変数1単位の変化に対するKPI・業績の変化量 |
| タイムラグ | 影響が顕在化するまでの月数レンジ |
| 前提 | 転嫁率・ヘッジ比率など、感応度の成立条件 |

- この5要素を1組のレコードとして版管理することが、要求定義§3の「担当者が交代しても組織に型が残る」を満たす手段である。
- レポートはこのモデルの投影として生成されるものであり、逆であってはならない。

## 3. 機能要件（要求からの対応）

| 要求定義§4の要求 | 満たすべき機能要件 |
|---|---|
| 信号機判定付き月次配信 | 指標を継続観測し、平常レンジと閾値に照らして状態判定を自動付与する |
| 感応度マトリクスの毎月更新 | 翻訳モデルを月次で再計算し、前月差分と変更理由を明示する |
| 3シナリオ試算 | 同一モデルにベース／弱気／強気の入力集合を適用し、12〜24ヶ月の業績影響を出力する |
| 根拠・出所の添付 | 全出力数値から、算出根拠・一次情報の出所・参照した過去事例へ遡及できる |
| 経営会議用サマリー生成 | 詳細出力とは別に、結論と提言に圧縮した意思決定者向け出力を生成する |
| 乖離診断とアラート | 会社公表予想と自社シナリオを突合し、閾値超過を検知して通知する |
| 精度の継続証明 | 過去期間にモデルを遡及適用し、実績との誤差を記録・公開する |

## 4. データ要件

- 入力は3系統に分かれ、それぞれ扱いが異なる。
- **公開マクロ・統計データ** — 一次基盤とし、自動取得と履歴保持を必須とする。
- **公開個社データ** — 感応度を「概算」から「実測」に引き上げる根拠源であり、セグメント別構成の取得を要件とする。
- **顧客社内データ** — 上位ティアのみで扱い、顧客資産として分離保管し、モデル共通部へ混入させない。
- 要求定義§6により、**再配布制約のある商用データを顧客向け出力に含めてはならない**。
- この制約は運用方針ではなく、出力生成時に機械的に担保する。

## 5. アーキテクチャ上の分離要件

- グロスマージンと横展開コストを決定するため、以下3層を物理的に分離する。
- **共通コア** — マクロ変数定義、伝達経路の型、シナリオ生成、検証機構。全顧客で共有する。
- **業種テンプレート** — 業種固有の変数・KPI・典型感応度。新業種の追加はこの層の追加のみで完結する。
- **顧客個別レイヤー** — 自社セグメント構成、社内データ結合、個別前提。
- 新業種の立ち上げが共通コアの改修を要する場合、それは分離の失敗とみなす。

## 6. 非機能要件

- **根拠追跡性**（最優先） — 出力の全数値が一次情報まで遡及可能であること。
- **再現性** — 同一入力・同一モデル版で同一出力が得られ、全出力に版と改定履歴を付すこと。
- **鮮度** — 月次サイクルに間に合う更新完了。閾値超過は検知即時に通知すること。
- **拡張性** — 業種追加のコストが逓減する構造であること。
- **説明可能性** — 顧客が社内・投資家に対して自らの言葉で再説明できる粒度で根拠を提示すること。

## 7. スコープ外

- 要求定義§8に同じ。
- 加えて、投資判断・売買執行に直結する自動化機能は本システムの責務に含めない。

## 8. 段階的実現

- Y1はシード顧客での翻訳モデル構築と、最低1業種でのバックテスト成立を充足基準とする。
- Y3は第2業種の立ち上げが共通コア無改修で完了することを基準とする。
- これをもって業種テンプレート層の分離が実証されたとみなす。
