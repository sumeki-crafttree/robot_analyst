# ロボエコノミスト MVP 要件定義（概要 / System Requirements Overview）

**版**: v3.0（2026年8月24日 / MVP）
**上位文書**: [ミッション・ビジョン](01_mission_vision.md) / [要求定義](02_requirement_business.md)
**位置づけ**: 要求を、1週間・月1万円で実装可能なシステム要件へ翻訳する。詳細スキーマとIaCは下位の設計書・コードに委ねる。

---

## 1. 全体構成

- データパイプラインとWebアプリを**単一リポジトリ**に置き、Terraformで同じGCPプロジェクトへ展開する。
- データは `data source → original → raw → processed → product → report` の6層で流す。
- 各層は前層の出力のみを入力とし、後層から前層への逆流を禁止する。

| 層 | 実体 | 責務 | 不変性 |
|---|---|---|---|
| data source | TDnet | 外部。取得のみ行い、加工しない | — |
| original | GCS | 取得したバイト列を原本のまま保存する | 不変 |
| raw | GCS / BigQuery | 原本を機械可読にする最小変換のみ。意味は加えない | 再生成可 |
| processed | BigQuery | 正規化・ファクト抽出・テーマ付与を行う | 再生成可 |
| product | BigQuery | 人とレポート生成の双方が直接引くスキーマ | 再生成可 |
| report | GCS / Cloudflare Pages | アナリストレポートを生成し配信する | 版で保存 |

- **original と raw の境界は「意味を足したか」で引く。** PDFをテキスト化する行為はrawであり、そこから事実を切り出す行為はprocessedである。
- original以外の全層は、originalからいつでも再生成できること。これがモデルやプロンプトの差し替えを可能にする。

## 2. データソース要件

| ソース | 取得方式 | 更新頻度 | 用途 |
|---|---|---|---|
| 適時開示（決算説明資料含む） | TDnet | 随時 | 唯一の一次ソース |

- 取得は冪等とし、同一期間を再実行してもoriginal層が重複しないこと。
- **取得は日次で回す。**
- 判断根拠は、要求定義§3の「毎日使って嬉しいデータ基盤」が週次更新では成立しないためである。レポート生成は週次、データ取り込みは日次と、頻度を分離する。

## 3. 要素技術の要件

| 要求（要求定義§4） | 満たすべき要件 |
|---|---|
| peer／パートナー／customerのマスタ保持 | 企業マスタと、ウォッチ企業→関連企業の関係を表すブリッジを保持する |
| 適時開示のマスタマージ抽出 | 証券コードでマスタと突合し、関連企業の開示のみを対象化する |
| ファクトの抽出 | 開示本文から、主体・時点・事象・数値を構造化して切り出す |
| 共通マクロテーマのマッピング | 事前定義したテーマ軸へファクトを分類する |
| 自社への示唆のマッピング | 各ファクトに、ウォッチ企業ごとの意味を紐づける |

**企業マスタについて**

- 初期マスタは人手で作成する。自動リストアップは独立した開発項目であり、1週間では品質を担保できない。
- **マスタの網羅性が、プロダクトの網羅性の上限を直接決める。** マスタにない企業の開示は構造的に拾えない。
- したがってマスタは、抜けが判明した時点で行追加のみで補える形にする。

**マクロテーマについて**

- テーマは `dim_macro_theme` として**事前定義したマスタで持つ**。
- 判断根拠は、LLMに毎回自由生成させると表記が揺れ、企業横断の比較が成立しなくなるためである。
- テーマの追加・改廃はマスタの更新で行い、過去データへの再付与はprocessed層の再生成で吸収する。

## 4. プロダクトデータセットのスキーマ要件

- 全レコードは開示の識別子と原文位置を保持し、レポートの記述から出所へ遡及できること。
- **命名と粒度は、開発者がアドホックに引くことを前提に決める**（要求定義§3）。

| テーブル | 保持内容 |
|---|---|
| `dim_company` | 企業マスタ。証券コード・名称・業種のみを持ち、関係は持たない |
| `bridge_watch_company` | ウォッチ企業 × 関連企業。関係区分（peer／partner／customer）と優先度 |
| `dim_macro_theme` | 共通マクロテーマの定義 |
| `fact_disclosure` | 適時開示の原本メタデータ。マスタ突合の結果を含む |
| `fact_extracted_fact` | 開示から抽出したファクト。主体・時点・事象・数値・原文位置 |
| `fact_theme_mapping` | ファクト × マクロテーマ。横断比較の入力 |
| `fact_implication` | ファクト × ウォッチ企業への示唆 |

## 5. レポート要件

- プロダクト層を入力に、**ウォッチ企業ごとに**アナリストレポートを週次で自動生成する。
- 関連各社の当週のファクトを、関係区分（peer／partner／customer）ごとに提示する。
- マクロテーマ軸で各社の動きを横断比較する。
- 各項目に自社への示唆と、出所へのリンクを併記する。
- 生成物はGCSに版として保存し、Cloudflare Pagesで閲覧可能にする。
- 生成完了と失敗はメールで通知する。

## 6. 技術スタックとインフラ要件

- **GCP** — GCS（original・raw・report）、BigQuery（processed・product）、Cloud Run Jobs（バッチ）、Cloud Scheduler（起動）、Secret Manager（認証情報）。
- **GitHub** — ソース管理とCI。mainへのマージでTerraformとジョブイメージを反映する。
- **Terraform** — 全インフラをコード化し、stateはGCSに置く。
- **Cloudflare** — Pagesでレポートを配信し、ドメインとDNSを管理する。
- 認証情報はSecret Managerのみに置き、リポジトリへコミットしない。

## 7. コスト要件（上限 月1万円）

| 項目 | 想定 | 月額 |
|---|---|---|
| GCS | 原本と中間生成物の保存 | 約100円 |
| BigQuery | 無料枠（保存10GB／クエリ1TB）内 | 0円 |
| Cloud Run Jobs | 日次取込＋週次生成、無料枠内 | 0円 |
| Cloud Scheduler | ジョブ2本、無料枠内 | 0円 |
| Cloudflare Pages | 無料プラン | 0円 |
| LLM API | ファクト抽出＋示唆付与＋レポート生成 | 3,000〜6,000円 |
| 予備 | 再実行・再生成分 | 残り |

- **変動費はLLM API利用料のみであり、ここが唯一の超過リスクである。**
- 開示件数に比例して増えるため、**用途でモデルを分ける**。ファクト抽出とテーマ付与は件数が多いため安価なモデルを用い、レポートの文章生成のみ高性能モデルを用いる。
- 1回の実行に投入するトークン量に上限を設け、超過時は処理を中断してアラートを出す。
- processed層の再生成はLLMを再度呼ぶため、無制限の再実行を禁止し、実行回数を記録する。

## 8. 非機能要件

- **遡及可能性** — レポートの全記述が開示原本まで辿れること。
- **再生成可能性** — original層以外は、originalからいつでも再構築できること。
- **冪等性** — 同一日の再実行が重複データを生まないこと。
- **網羅性** — マスタに含まれる企業の開示に、取りこぼしがないこと。
- **拡張性** — ウォッチ企業・関連企業の追加が、マスタへの行追加で完結すること。
- **可読性** — プロダクト層を開発者がアドホックに引けること。
- **コスト可観測性** — 月次の実績コストを確認でき、上限接近時に気づけること。

## 9. 実装順序（7日間）

| 日 | 実施内容 |
|---|---|
| 1 | リポジトリ構成、Terraformでのプロジェクト・GCS・BigQuery・Secret Manager構築 |
| 2 | 企業マスタとテーママスタの初期作成、TDnet取得（original層まで） |
| 3 | raw層。PDF・XMLの機械可読化 |
| 4 | processed層。ファクト抽出とテーマ付与 |
| 5 | product層。示唆マッピングとスキーマ確定 |
| 6 | アナリストレポートの自動生成と配信 |
| 7 | Cloud Schedulerでの日次・週次実行、通しテスト、コスト実測 |

- 遅延した場合に削る順序は、①示唆マッピングの精度、②テーマ横断比較、③レポートの表現とする。
- **product層までが動いていること（Day 5まで）を死守する。** 要求定義§3の第三の要求は、レポートが未完成でもこの層が立っていれば満たされる。
